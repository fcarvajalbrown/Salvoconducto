# Salvoconducto — Adversarial red-team (2026-08-09)

Independent subagent, web-grounded, tasked to disprove the product. 8 questions, most-dangerous
first. Through-line of the four deadliest: **we claim to have built the platform's own primitives,
and we claim "proof" for a prototype where the prover controls everything.**

## Two concrete code issues it found
- `src/broker.mjs` writes the raw sensitive `value` into every receipt → the "minimization" tool
  keeps a plaintext second copy of the exposed data, contradicting our own threat model
  (ephemeral / no-retention / crypto-shred). Fix: store a redacted/hashed reference, or relabel
  the ledger as deliberate audit evidence.
- The demo lets the user grant, and shows "20 fields," but the real Passport is ~6 nested
  categories, and a blank grant-everything default is the theater the critique names.

## The 8 questions (attack → hardest honest fix)

1. **Egoist already ships scoped requests, purpose, expiry, receipts, revocation. What did you
   build?** (Judge is Egoist; our four pillars map 1:1 to ego.ist/developer.) → Stop claiming we
   *built* minimization/receipts/revocation; we *consume* the Passport's primitives and add the
   agent-delegation + proof + honesty layer.
2. **You admit already-read can't be undone, so "provable revocation" proves the event that no
   longer matters.** (Invariant Labs MCP exfil; Willison lethal trifecta; OWASP LLM02/06;
   unlearning is unsolved.) → Make minimization the headline; revocation is the backstop for
   residual *future* reads, not a fix for the past.
3. **Your auth server is an in-tab JS Map with the HMAC key in the same tab — signer = attacker,
   so it's theater by your own definition.** (Browser can't hold a secret; a client-controlled
   hash chain is tamper-evident to nobody without an external witness — Rekor/TSA/CT.) → State the
   simulated trust boundary FIRST; drop "tamper-evident" (call it an integrity check) unless we
   anchor to an external witness.
4. **Open Agent Passport already publishes signed, hash-chained decision receipts + a suspend
   registry; the category is crowded** (Astrix, Descope, WorkOS FGA, Auth0 for AI Agents, Entra
   Agent ID). → Claim placement/audience novelty (citizen-side, per-field), not mechanism. Warn:
   field-minimization has prior art in W3C VC / SD-JWT (RFC 9901) and Kantara.
5. **RFC 7662 itself permits caching a revoked token; RFC 7009 says revocation propagates with
   delay.** → Say "verified at the enforcement point," not "provable"; cite RFC 7662 §4 no-cache.
6. **GDPR puts minimization on the controller, not a user slider; users rubber-stamp dialogs; and
   your ledger stores the plaintext field.** (GDPR Art 5; Felt SOUPS'12; habituation; Nouwens
   CHI'20; Schneier's theater definition.) → Fix the grant-all default (agent's declared narrow
   scope is the default, user only narrows); stop storing raw value in receipts.
7. **Real Passport is ~6 categories not "20 fields," and your "judging pillars" are the
   submission-form questions, not the published "Judges will look for" list.** → Pure hygiene: fix
   the count/structure and map each demo beat to the six actual criteria.
8. **The capability token is Macaroons (2014) / Biscuit (2021); the IETF attenuating-tokens draft
   and NIST NCCoE paper are unadopted (individual I-D; concept paper).** → Own the lineage as a
   deliberate choice; downgrade the speculative citations to "early signals"; lead standards with
   the normative RFC 7662 (and SD-JWT if we add selective disclosure).

## Highest-leverage single fix
Reposition from "a better permission/revocation system" (Egoist has it; OAP published it) to
**the citizen-side, per-field, purpose-bound minimization + honest already-read accounting layer
for high-stakes personal delegation** — the one wedge no competitor and not even Egoist occupies —
and state the simulated trust boundary up front, not in a footnote.
